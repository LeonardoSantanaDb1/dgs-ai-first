# Exercício 3.1 — Structured Output e Verificações Determinísticas (Harness Engineering)

## Contexto

Estou participando da Certificação AI First e atuo no papel de Desenvolvedor.

Estou implementando o Exercício 3.1, cujo objetivo é aumentar a confiabilidade do assistente de IA da NovaTech através da combinação de:

- Structured Outputs;
- validações determinísticas em código;
- guardrails de negócio.

Quero que você atue como um Desenvolvedor Sênior especializado em TypeScript e IA Generativa.

Considere que este código fará parte de um ambiente de produção e deverá priorizar clareza, robustez, manutenibilidade e governança.

## Cenário

O assistente utiliza um pipeline RAG para responder perguntas dos atendentes.

Hoje as respostas são retornadas em texto livre, permitindo que respostas sem fonte ou em desacordo com as regras de negócio sejam aceitas.

O objetivo deste módulo é validar essas respostas antes que sejam entregues ao usuário.

## Stack

- TypeScript
- Zod
- Pino
- Azure Functions
- Azure OpenAI
- Azure AI Search

## Local da implementação

```
src/services/response-validator.ts
```

## Requisitos funcionais

Implemente um módulo responsável por:

1. Validar o Structured Output utilizando Zod.

O modelo deve retornar obrigatoriamente:

- answer
- source_document
- confidence_score

2. Rejeitar qualquer resposta que não esteja em conformidade com o schema.

3. Aplicar os seguintes guardrails determinísticos.

### Guardrail 1

Toda resposta deve possuir o campo `source_document`.

Caso esteja ausente ou vazio:

- bloquear a resposta;
- registrar o motivo em log;
- retornar uma resposta segura.

### Guardrail 2

Quando a resposta mencionar simultaneamente:

- carga perigosa;
- devolução;

o validator deve impedir respostas que afirmem que a devolução é permitida.

Nestes casos:

- bloquear a resposta;
- registrar o motivo em log;
- retornar uma resposta segura.

## Requisitos técnicos

A implementação deve:

- utilizar TypeScript Strict;

- separar responsabilidades;
